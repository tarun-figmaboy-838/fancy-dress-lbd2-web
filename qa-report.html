The six bugs

1 · The yellow cube answered clicks FIXED

The block is not special. Unity attaches a Button to a great deal of artwork that no script ever listens to, and this port gave every one of them the full control treatment — pointer cursor and press tint.

The rule now lives in one place: a Button is a control only while something is listening to it — an inspector-wired call, or a runtime addClickListener. Everything else is dropped out of hit testing, so a tap falls through to the artwork behind: no cursor, no flash, no click. Nothing moves and nothing changes size.

Three cases are named explicitly, because a blanket rule would have broken them: the draggable item (claims its node, so dragging is unaffected; becomes inert only once it is resting in a pan), spawned blocks (two prefabs carry an empty Button, one carries none), and the tutorial's −, which had no listener in the original and used to light up after the first block and do nothing — it now removes a block, the way the six levels do.

2 · No hover feedback on Next / Try Again FIXED

Unity's ColorTint transition only fires on press, so with a mouse there was no way to tell Next or Try Again from the artwork around them until after clicking.

Hover

scale 0.96, brightness 0.92
Timing
0.13 s ease-out both ways
Applies to
All six levels' Next, Try Again, Check, + and −, plus the tutorial's, Let's Go and the new voice button

Three deliberate constraints. It never writes transform — the engine owns that property and rewrites it on every relayout, and Let's Go has a scale tween running on it every frame; the independent scale property composes instead of fighting. It never fires on touch, because :hover sticks after a tap and would leave the last button looking permanently lit. And it never lights up something unusable — disabled buttons, scenery, the backdrop and the draggable item are all excluded.

3 · Hand cursor over the balance and passive art FIXED

Resolving the effective cursor for every node in both scenes, across all six levels and the tutorial:

Nodes wrongly showing a hand
Before115
After0

Most of it was the 88 alpha-0 slot markers — invisible, but sitting exactly over the plates and arms, each carrying an empty Button. The start screen was the other half: Intro is anchored 0,0 → 1,1, so the whole 1920×1080 picture was a Button claiming a pointer cursor, and because cursor inherits, everything inside it did too. Any Button covering half the canvas or more is now treated as a backdrop: no cursor, no feedback. The threshold is measured, not guessed — the largest real control in either scene is Let's Go at 8.5% of the canvas.

It no longer answers taps either. That full-screen button's only job was to play the title line, which made the whole banner a hair-trigger — a tap anywhere, reaching for Let's Go or just steadying the tablet, restarted the line over whatever was already speaking. The voice-over button takes the job over and switches the backdrop off, and only once it is actually on screen, so a missing clip leaves the authored behaviour as the fallback rather than making the line unreachable.

One hand deliberately stays: grab on the item while it is waiting to be placed. Dragging it onto the balance is the whole mechanic, and the instruction bar literally asks for it. It is a different cursor from pointer, it appears only once the bar has asked, and it is gone the moment the item is in a pan.

4 · Unbalanced and balanced looked the same FIXED

Every curve in the authored tilt clips is two keys with zero tangents, so the pose at clip fraction t is exactly smoothstep(t) = 3t² − 2t³ — and smoothstep is flat at both ends. Feeding it the raw weight ratio put the one reading the child has to make in the flattest part of the curve.

NeededLevelOne block out — beforeOne block out — after
7Watermelon, Cup1.11°13.14°
6Pumpkin, Shoe1.48°13.33°

3Tutorial5.19°14.67°

The exact comparison in the report — 8 balls against 7 — goes from 1.1° to 13.1°, a 12× difference, and the last block now swings the pan 34 units instead of 3. Too many blocks leans the other way by the same amount, so too few and too many are opposite pictures rather than two shades of almost-level.

The pose is chosen first now and the clip time derived from it by inverting the smoothstep. Three properties are kept: every block still moves the balance (by an equal step, where the old steps crowded all their travel into the middle of the count); the authored poses are untouched at both extremes and at level; and the tween interpolates the pose rather than the ratio, so the final block carries the beam smoothly all the way down instead of snapping flat on the last frame.

5 · Press / highlight flash on the cube FIXED

The same root cause as #1, so it goes away with it. Two things were tightened on top. The press class is no longer added to scenery at all — the exclusions used to live only in the stylesheet, so a press state could sit on a node with no business reporting one. And a cancelled touch no longer sticks: the class was cleared on pointerup and pointerleave but not pointercancel, which is what a system gesture fires instead of either, leaving the button dimmed and shrunk for good. That one was latent, not reported.

6 · + and − fully blue before the item is placed FIXED

A level opens on "Place the orange on the balance", and until that is done neither button can do anything — but both sat there in full blue. The cause was a method whose entire job was to decouple appearance from capability: it switched the buttons off while explicitly forcing their alpha back to 1. It is gone.

The same defect was hiding in Try Again after too few blocks, which lit both buttons immediately after emptying the pan — so − came back in full blue with nothing to remove.

A switched-off control fades — it keeps its own colour and simply recedes. Draining the colour to grey was tried first and rejected on review: it read as a different, broken-looking button rather than as the same one waiting its turn.

The fade depth is one number for the whole game, 0.4, because it is the only signal that a button is unavailable and so has to be unmistakable and identical everywhere. The scenes disagreed — Level 1 authored 0.6, levels 2–6 0.4, the tutorial 0.5 — so a disabled button was visibly more present in Level 1 than in the level after it. Switching on eases rather than cutting.

Scope: all six levels had this, through three separate per-level routes. The tutorial did not — its controller always set alpha alongside interactable.

Added: interaction sound effects

The game answered the child in only two places — the voice-over and the success sting. Every gesture in between was silent. Nine short sounds now cover the gaps, synthesised with WebAudio, so nothing was added to the payload: the build is byte-for-byte the same size, and no new file ships. That follows what the project already did for the success sting, for the same reason.

MomentSound

Three things they are built around. They are quiet — every peak is under half the success sting's, because the voice-over is the channel that actually teaches and a sound effect must never hide a word of it. They are short, no envelope past 200 ms, because a child taps + eight times in a row. And they are dry; the echo bus is kept for the celebration, since echo on a repeated tap becomes mud.

The + and − are pitched deliberately: one step up a major pentatonic per block, so the count is audible as well as visible — which is the subject of the game. A pentatonic was chosen because it has no interval that can sound wrong whichever order the notes arrive in.

Every call is fire-and-forget and wrapped so a sound can never break a game action; if the browser refuses an audio context, the game behaves exactly as before. The layer switches off with Engine.Audio.setSfx(false) and its level against the voice-over is one number, Engine.Audio.setSfxVolume(v). God Mode has a Play all SFX button that auditions every sound in turn.

One bug found after the first attempt. AudioContext.resume() is asynchronous, and a suspended context has a frozen clock — so scheduling against currentTime before it had actually started put the whole envelope in the past and the sound was never produced. The first effect after a tab regained focus was silent for exactly this reason. sfx() now waits for the resume before it plays, and the levels, which were set at about half the success sting's, were roughly doubled.

Found while testing the sound layer

Three defects surfaced only because the effects were reported as inaudible and the cause was chased rather than guessed at. Two of them were mine; the third is a production issue that predates this work.

1 · The whole effects layer was silent FIXED

The new master gain was named sfxBus — and sfxBus was already the echo bus's state variable in the same scope. var sfxBus = null runs at load and overwrites the hoisted function, so every effect threw "sfxBus is not a function". The success sting kept playing because it routes through bus(), not through the new one — which is exactly the symptom reported: celebration audible, everything else silent.

A try/catch written to stop a sound effect breaking a game action is what swallowed the error and hid this across three attempts at the wrong fix. It now warns once per sound instead of discarding it.

Proven by execution, not by reading. engine.js is run against a stubbed Web Audio API with every sound fired, counting the oscillators each creates:

Before19 oscillators0 — all silent
After19all 9 play

That test is now part of the QA sweep. It replaced a static check for name shadowing, which produced a false positive — a regex cannot tell same-scope shadowing from two functions that merely share a local name in different scopes.

2 · Audio output was never unlocked FIXED

Two further reasons a first sound can be lost, both fixed on the way: AudioContext.resume() is asynchronous, and a suspended context has a frozen clock — so scheduling against currentTime before it has started puts the envelope in the past and nothing is produced. And iOS Safari hands back a context that reports itself running but stays silent until a real source has been started inside a genuine gesture. The first gesture on the page now pushes one silent sample through the context, which is what actually opens output.

3 · The CDN was serving mismatched code FIXED

Observed live: X-Vercel-Cache: HIT with Age: 1832 on engine.js while controllers.js was current. The scripts are not content-hashed — engine.js is always engine.js — and vercel.json set a cache policy only for /assets and /js/data.js. Everything else fell to the default and was cached independently, so a visitor could run engine.js from one deploy against controllers.js from another. That is a mismatched-build class of failure, and it predates this work. /js and /css now revalidate at the edge as well as in the browser.

Added: controls that arrive

Check, Next and Try Again appear part-way through a round, and did so in a single frame — which reads as a glitch rather than as something being offered. They now scale and fade up with a slight overshoot over 0.42 s.

It runs on the sprite layer, never on the element the engine positions, for the same reason the glow and the item pop do: applyLayout owns transform on every node and rewrites it on any relayout. It is also guarded on the node's current state — enableCheckButton re-shows Check after every block, so without that guard it would pop again on each one.

New regression guards

Two live-DOM checks were added to the God Mode developer layer, both included in Run all. They are stripped from the published learner build and cannot affect it.

  • Cursors — reads the cursor the browser actually resolved for every visible node and fails on any hand that is not a Button with a listener or an item that can still be picked up.
  • Press — drives the reported repro for real: finds the sample block, asserts it takes no pointer events, asserts a tap at its centre lands on the counter behind it, then dispatches a real pointerdown and asserts the block's computed filter, scale and opacity are unchanged before, during and after.

Notes worth knowing

  • Two deliberate behaviour changes, both flagged rather than slipped in: the tutorial's − now works — it had no listener in the original, so it did nothing at all while being lit from the first block onward — and tapping the start-screen background no longer dims the whole picture (it still plays the title line).
