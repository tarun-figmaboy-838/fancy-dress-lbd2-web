The six bugs

1 · The yellow cube answered clicks FIXED

The block is not special. Unity attaches a Button to a great deal of artwork that no script ever listens to, and this port gave every one of them the full control treatment — pointer cursor and press tint.

The rule now lives in one place: a Button is a control only while something is listening to it — an inspector-wired call, or a runtime addClickListener. Everything else is dropped out of hit testing, so a tap falls through to the artwork behind: no cursor, no flash, no click. Nothing moves and nothing changes size.

Three cases are named explicitly, because a blanket rule would have broken them: the draggable item (claims its node, so dragging is unaffected; becomes inert only once it is resting in a pan), spawned blocks (two prefabs carry an empty Button, one carries none), and the tutorial's −, which had no listener in the original or here and used to light up after the first block and do nothing.

2 · No hover feedback on Next / Try Again FIXED

Unity's ColorTint transition only fires on press, so with a mouse there was no way to tell Next or Try Again from the artwork around them until after clicking.

Hover
scale 1.05, brightness 1.07
Press
scale 0.96, brightness 0.92
Timing
0.13 s ease-out both ways
Applies to
All six levels' Next, Try Again, Check, + and −, plus the tutorial's, Let's Go and the new voice button

Three deliberate constraints. It never writes transform — the engine owns that property and rewrites it on every relayout, and Let's Go has a scale tween running on it every frame; the independent scale property composes instead of fighting. It never fires on touch, because :hover sticks after a tap and would leave the last button looking permanently lit. And it never lights up something unusable — disabled buttons, scenery, the backdrop and the draggable item are all excluded.

3 · Hand cursor over the balance and passive art FIXED

Before115

Most of it was the 88 alpha-0 slot markers — invisible, but sitting exactly over the plates and arms, each carrying an empty Button. The start screen was the other half: Intro is anchored 0,0 → 1,1, so the whole 1920×1080 picture was a Button claiming a pointer cursor, and because cursor inherits, everything inside it did too. Any Button covering half the canvas or more is now treated as a backdrop: still clickable, no cursor, no feedback. The threshold is measured, not guessed — the largest real control in either scene is Let's Go at 8.5% of the canvas.

One hand deliberately stays: grab on the item while it is waiting to be placed. Dragging it onto the balance is the whole mechanic, and the instruction bar literally asks for it. It is a different cursor from pointer, it appears only once the bar has asked, and it is gone the moment the item is in a pan.

4 · Unbalanced and balanced looked the same FIXED

Every curve in the authored tilt clips is two keys with zero tangents, so the pose at clip fraction t is exactly smoothstep(t) = 3t² − 2t³ — and smoothstep is flat at both ends. Feeding it the raw weight ratio put the one reading the child has to make in the flattest part of the curve.

The exact comparison in the report — 8 balls against 7 — goes from 1.1° to 13.1°, a 12× difference, and the last block now swings the pan 34 units instead of 3. Too many blocks leans the other way by the same amount, so too few and too many are opposite pictures rather than two shades of almost-level.

The pose is chosen first now and the clip time derived from it by inverting the smoothstep. Three properties are kept: every block still moves the balance (by an equal step, where the old steps crowded all their travel into the middle of the count); the authored poses are untouched at both extremes and at level; and the tween interpolates the pose rather than the ratio, so the final block carries the beam smoothly all the way down instead of snapping flat on the last frame.

5 · Press / highlight flash on the cube FIXED

The same root cause as #1, so it goes away with it. Two things were tightened on top. The press class is no longer added to scenery at all — the exclusions used to live only in the stylesheet, so a press state could sit on a node with no business reporting one. And a cancelled touch no longer sticks: the class was cleared on pointerup and pointerleave but not pointercancel, which is what a system gesture fires instead of either, leaving the button dimmed and shrunk for good. That one was latent, not reported.

6 · + and − fully blue before the item is placed FIXED

A level opens on "Place the orange on the balance", and until that is done neither button can do anything — but both sat there in full blue. The cause was a method whose entire job was to decouple appearance from capability: it switched the buttons off while explicitly forcing their alpha back to 1. It is gone.

The same defect was hiding in Try Again after too few blocks, which lit both buttons immediately after emptying the pan — so − came back in full blue with nothing to remove.

Dimming alone was not enough: the authored disabled alpha turns a blue button into a paler blue, which at a glance is still the live control it is drawn as. Draining the colour is what makes it read as grey, so a disabled control also takes grayscale(0.9). Audited: 15 nodes can take the disabled look and all 15 are real controls — the exclusions are what stop it greying the boat, the orange and the tutorial's book, whose Buttons are authored non-interactable.

Scope: all six levels had this, through three separate per-level routes. The tutorial did not — its controller always set alpha alongside interactable.

New regression guards

Two live-DOM checks were added to the God Mode developer layer, both included in Run all. They are stripped from the published learner build and cannot affect it.

  • Cursors — reads the cursor the browser actually resolved for every visible node and fails on any hand that is not a Button with a listener or an item that can still be picked up.
  • Press — drives the reported repro for real: finds the sample block, asserts it takes no pointer events, asserts a tap at its centre lands on the counter behind it, then dispatches a real pointerdown and asserts the block's computed filter, scale and opacity are unchanged before, during and after.

Notes worth knowing

  • Two deliberate behaviour changes, both flagged rather than slipped in: the tutorial's − now stays greyed for the whole demo (it has no function there, in the original or here), and tapping the start-screen background no longer dims the whole picture (it still plays the title line).
  • Level 1 authors a disabled alpha of 0.6 where levels 2–6 use 0.4. Both read clearly as disabled now that colour is drained, so this is not a bug — but Level 1's greyed buttons are slightly more visible than the others'. Not changed.
